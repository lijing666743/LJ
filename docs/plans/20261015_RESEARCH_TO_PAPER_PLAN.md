## 4. 第 1 周的限定诊断任务

诊断上限建议为 5 个工作日、约 12—16 小时人工分析。先用现有冻结评估及训练侧日志，缺失字段才追加被动诊断；不要一开始同时更改 reward、路由结构和 CPU 策略。

### D1：确认回落在哪个任务阶段发生

以 seed44 的 32k→36k 为首要配对，36k→40k 为恢复对照，20k→40k 为中期到终点参考；用 seed42/43 的相同阶段作控制。保留五个开发场景，不只挑表现最差的一场。

逐任务核对生成、工作量、期限、Route 绑定、首次 TX、首次 CPU、完成或终止阶段。已有证据是失去完成的 86 个任务中 49 个在 36k 未绑定即过期，不能把这 49 个全部直接归因为 Defer：还需判断 EDF 队首阻塞、合法候选、每槽一次分配容量、任务已无可完成余量等因素。

交付：lost/gained 任务配对及机制分类，每个归因标记为“事实”“相关线索”或“干预支持”，不能把终止阶段名称写成根因。

### D2：Route/Defer 是否存在可解释的策略改变

只在有未绑定任务且动作 active 的时隙统计真实叶动作、Defer 次数与涉及任务数、连续等待长度、首次绑定时的 slack、合法候选数、Local/Remote 分数与概率差距。Remote 概率总量与实际叶 argmax 分开。

检查模型是否把同一任务持续 Defer，或其他队首阻塞导致后续任务没有获得决策机会。若已有遥测不足，新增被动字段须验证开启前后动作、RNG、环境轨迹和 checkpoint 均不变。

### D3：额外 CPU 能耗花在什么服务上

已有报告指出 seed44 相对 Heuristic 多出的约 67.91 J 中约 92% 来自 CPU；这只定位成本来源。进一步按 UAV、实际执行频率、实际服务 cycles、任务终局、deadline slack、排队和闲置条件分解。

优先区分：为更多有效计算支付的成本、对最终 EXPIRED/TRUNCATED 任务已消耗的 CPU、过高频率、可服务却 idle、队列长期等待、能量降档或能量不足。只有轨迹支持的实际能耗才能归属任务，不用代理时间或理论峰值伪造实际能耗。任务终局回看可用于离线解释，不能作为 actor 输入或训练标签。

### D4：后期 PPO 更新是否存在异常信号

核对 28k—40k 的 Route 与 CPU 分支 KL、clip fraction、entropy、有效样本、advantage 分布、value/Q 误差与梯度范数等**现有字段**。缺失诊断记 NA，不补造历史训练数值。检查学习率与探索退火的真实配置，不能把正常退火结束或单个高 loss 当作根因。

### D5：必要时做一个冻结开发干预

若 D1—D4 已缩小到 Route 或服务模块，可以在已见开发场景做有限策略组合干预，例如冻结路由搭配固定服务策略。每个组合从 reset 重跑，使用相同外生过程，并验证循环 hidden、动作分布和顺序接口。更换策略会改变后续状态，不能把两个不同状态轨迹的分数直接当作相同状态因果对照。

这类干预只检验模拟系统中的机制假设，不是正式算法优势证据；不产生 oracle 训练数据，不用最终测试 seed，也不把替换服务后的旧 C checkpoint 当作重新训练的模块模型。

### 本周决策

- 发现实现错误：先构造能复现错误的测试，修复后检查所有受影响方法。受影响的既有训练/评估不能静默升级为修复后结果；需要重新评价，必要时重新训练。
- 无实现错误、存在清楚的单一机制：允许提出一个限定改动，记录理由与影响，再决定是否进入第 2 周小型验证；不同时调整多个组件。
- 证据不足：保留当前 C，结束开放式诊断，推进基线与公平比较。研究可以报告种子敏感性和能耗代价，不需要先把它“调到稳定”才开始写作。

## 5. 第 2—3 周的工程交付

### E1：共同服务的路由实验接口

实现 MTS 路由、C 路由、Heuristic 路由与固定非 Route 服务的组合适配。维护相同观测、动作 index、mask、proposal/execution、槽末入队与下一槽服务。MTS/C 路由模型均从零训练，独立 run 身份；不复用原 C40k 权重来构造有训练公平性含义的路由结果。

验收：Local→CPU→DONE、Remote→TX→CPU→DONE、Defer/Idle、EXPIRED/TRUNCATED、任务/bit/cycle/能量守恒均有真实夹具；组合策略没有额外观测，没有同槽提前服务，固定模型重复评估一致。

### E2：MTS 学习链

核对原文 RNN/DQN 分工、QMIX mixer、replay、target network、探索和平均回报更新，明确当前单队首、有限 horizon、现有 reward 等适配。原文细节不能查清时，准确标为 MTS-inspired 方法，不能宣称忠实复现。

验收：TD target 在 terminal/truncated 条件正确；合法 mask、padding 与循环序列无泄露；有效样本能产生真实参数更新；非空 optimizer/replay/探索 RNG 保存恢复一致；评估网络不更新。原文的 256 维 GRU 等数值是候选参考，不默认照抄，也不能仅为节省计算随意削弱基线。

### E3：Factorized-Action GAT-QMIX 完整控制

实现冻结方法中的图编码、循环局部 Q、七分支动作和单调 mixer，接入统一配置、runner、checkpoint 与评估。验证条件 mask 下的动作搜索边界，不能只验证 mixer 权重非负就宣布所有最优性性质成立。

验收：小动作域可枚举夹具、replay 序列/hidden、有效与 inactive 分支、target 更新、终止状态、完整恢复、跨方法拒绝错误 checkpoint，以及冻结评估可复现。方法正式训练前再次通过 Gate 0 和受影响环境回归；基线实现完成时按仓库要求执行必要完整回归。

### E4：统一评估及统计入口

现有 FormalEvaluationRunner 与 loader 绑定 C，需要增加明确的策略/模型适配入口，保留原四方法路径的兼容性。比较时核对外生过程与工作量，不要求不同策略下队列、任务结局或内生干扰相同。

验收：相同策略旧路径重放一致；新方法归入正确身份；确定性推理不消费训练探索 RNG；无优化器更新；防覆盖及来源 hash 有效。统计与图表由真实输出生成，不能复制历史 CSV 后换方法名称。

### 6.1 开发和正式用途

开发评估继续用 1042—1046。主比较固定 40k final，4k 间隔 checkpoint 仅用于学习过程诊断；主预算在开跑前写入协议。40k 不代表收敛，也不能把较慢的算法在 40k 表现差解读为所有预算下都差。

若决定统一延长主预算，必须在最终测试前对所有相关学习方法规定一致的延长与选择规则，并记录原因。不能只续训 seed44、只保留某个 seed 的最佳中期点或只增加 C 的预算。基线的 replay 更新频率可以遵循自身方法，但应公开对应成本。

为每个新增学习方法预留最多 3 套预先定义的开发配置，调参总主环境预算建议不超过每方法 80k；这是本计划建议的资源上限，不是已完成实验或通用标准。明确调参所用 seed、参数范围与选择准则，给基线充分而可追溯的机会；不要无限搜索到 C 获胜，也不要用调参不足的基线作结论。

### 6.2 预算估算与复用条件

核心 4 方法 × 5 seeds × 40k = **800k 主环境 transitions**。模块 2 方法 × 3 seeds × 40k = **240k**，扩至 5 seeds 为 **400k**。因此核心加模块的终点矩阵为 **1.04M—1.20M 主环境 transitions**。

已有 A/B seed42 各 16k、C 三 seeds 各 40k，合计 152k。在方法、环境、reward 与身份可复用的前提下，净新增学习进度约 **888k—1.048M**；实际算力还须加入旧边界重放、调参、工程夹具、shadow 辅助和评估。

如果 C 被改动，旧三 seed 40k 只保留为旧版本证据，新版 C 要重新构成完整矩阵，至少额外增加原本可复用的 120k。如果改动影响共享环境或服务，应重新核对所有相关组，不能只重跑受益方法。

A/B seed42 延长预算需按完整 periodic 状态恢复，并重放核对旧边界，不能加载 final 权重后称为无中断续训。C 如果延长超过 40k，当前 final 有 64 条 unused tail；须另行验证 periodic 恢复与 40k 边界重放路线。本计划默认先不超过 40k。

当前 seed44 十次四方法开发评估的 duration_seconds 合计约 2462 秒，每次约 221—282 秒，是已有 CPU 评估成本参考，不能推算 QMIX/MTS 训练耗时或保证新评估的墙钟时间。首周应测量代表性运行的 steps/s、更新耗时、最大内存、日志增长和恢复成本，再确定夜间运行队列。训练小时数暂不编造。

### 6.3 敏感性与两类主实验要求

优先在已冻结研究范围中选择两条轴，例如负载压力和资源异构强度，各设 3 个预先定义水平，基准水平共享，形成至多 5 个独立条件。水平以配置中的真实物理参数定义，在看新结果前固定。

8 周默认先对基准条件训练出的**冻结策略**做这些条件的敏感性评估，所有方法使用相同条件。这支持“冻结策略在指定条件变化下的表现”，不等价于每个条件重新训练后的最优比较，也不自动满足原方案对多个正式实验族的成立要求。

若论文要声称至少两类正式实验族中的优势，应另给代表性新条件安排各方法匹配的从零训练与多 seed 比较。增加一个完整核心条件约需 800k 主环境 transitions，不能藏在“补一张敏感性图”里；首周确认算力后决定是否扩展到 10 周。不要同时加入数量 OOD、实时射线追踪或轨迹控制。

## 7. 第 6 周最终测试与统计规则

1. 核验 seeds20042—20061 没有用于训练、调参、checkpoint 选择或开发诊断。若已经污染，先登记事实并在新结果揭晓前另行冻结一组；不能看成绩后换 seed。本轮没有全面核验该集合的历史使用情况，也没有运行它。
2. 方法、配置、预算、checkpoint 规则、敏感性水平和统计口径冻结后，全部方法在共同最终场景上评估。不同方法及 training seed 使用相同评估外生过程。任务总数由真实运行产生，不能继续假定为开发集的 605。
3. 完成率先在每个 training run 的共同评估集内用总 DONE / 总 generated 汇总，再报告训练重复之间的均值、标准差与全部单 seed 结果。保留逐场景差值与失败案例。
4. 主指标是截止期完成率/完成数；辅助报告总 CPU+TX 主动能耗、每完成任务能耗、EXPIRED/TRUNCATED、时延与执行成本。能耗口径不扩写为含飞行能耗的 UAV 总能耗。完成任务时延只针对成功样本，必须与失败率一起解释；空分母为 NA。
5. 统计单位以独立 training run 和评估场景为层级。5 training seeds × 20 场景不是 100 次独立训练；同一场景的多个任务共享队列及资源，也不能当作独立 Bernoulli 样本计算狭窄置信区间。
6. 预先固定主要比较 C 对 Heuristic 与 C 对 QMIX，以及 B→C 特征消融；模块比较单列。使用保留方法配对关系的区间估计，例如对训练索引和场景索引作交叉重采样，同一次抽样用于所有方法。说明 5 个 training seeds 仍较少、区间估计有限，不以 bootstrap 自动宣称显著。
7. 当前 shadow RNG 固定；最终报告注明哪些随机源变化、哪些不变。若要改变 shadow RNG，作为单独预定敏感性实验，不在主比较中静默改变。
8. 最终测试揭晓后只分析与写作，不继续据其调参。若发现真正实现错误，记录失效范围；新一轮方法开发后应使用新的最终测试协议，原测试转为已见数据。

区间与训练波动的报告原则参考 [Agarwal 等的 RL 统计评估研究](https://arxiv.org/abs/2108.13264)。具体实验数量和资源上限是本项目的拟定选择，不是该论文规定。

| 结果 | 第 4 周开始，第 6 周完成 | 完整系统比较、A/B/C 消融、MTS 模块比较、参数敏感性、机制与失败案例 | 真实日志、汇总数据、统计结果 |
| 讨论与局限 | 第 5—6 周 | seed 敏感性、能耗代价、代理与真实服务差异、仿真和适配边界 | 成功与失败 seed、最终评估及基线差异表 |

| 全文与附录 | 第 7—8 周 | 英文表达、参数/算法/符号、复现入口、参考文献、模板格式 | 编译、来源、数值与图表核对 |

公式、算法和复杂度说明优先提升可复现性：符号有定义、单位统一、任务/动作/时隙索引明确，方程前有用途、后有解释。不把经验学习曲线写成收敛定理，不把物理时间代理写成完成保证，也不照搬其他论文的最优性证明。

所有图追溯至真实 CSV/JSON 与生成入口；图像放 `plots/`，Dashboard CSV 放 `dashboard_logs/`，原始运行日志放 `logs/`。最终图制作时使用本项目科学绘图技能；当前阅读截图只属于文献审阅证据，不能混入实验图。

## 9. 决策点与停止条件

| 时间 | 必须决定什么 | 不满足时怎样处理 |
|---|---|---|
| 第 1 周末 | C 回落是否有可归因的修复；MTS 适配是否能保留核心机制 | 无根因就停止开放式诊断；缺少关键原文细节就标注或选一个后备 |
| 第 2 周末 | 方法、reward、比较范围和预算是否冻结 | 必须变更时留下新版身份和重跑范围；挤占后续实验则整体顺延，不能隐藏缺口 |
| 第 3 周末 | 基线是否通过工程验收并能实际学习 | 暂不进行昂贵矩阵；修复基线，不能把故障结果当作弱基线 |
| 第 5 周末 | 数据是否足以进入最终测试；是否仍需多实验族从零训练 | 确认主矩阵完整、源可追溯后再测试；否则优先延长实验阶段 |
| 第 6 周末 | 论文能支持哪些结论 | 胜出则报告条件与不确定性；接近则报告权衡；落后则诚实收缩贡献，不据最终测试继续调参 |

当前以完成任务数为主目标，能耗是必须公开的代价。若 C 在最终测试中仍高耗能但完成数更高，只能讨论性能—成本权衡；若与 Heuristic 完成率接近而能耗显著更高，需要直接承认该局限。不能把“没有显著差异”写成等效，也不能保证一份完整稿一定达到预期发表级别。

建议预留至 10 周的两种明确触发条件：基线关键细节无法在第 3 周前解决，或必须补一个独立训练实验族。延长窗口为 12/10—12/23，优先完成已确定的必要证据，不继续增加新算法。若每周只能投入约 10—15 小时，则应在首周重新排为约 10—12 周以上，而不是把全部工程任务压进相同日期。

算力不足时的削减顺序：先取消 GSTRL 等后备的额外实现和装饰图，再减少可选参数水平/额外实验族；保留真正学习基线、同预算 A/B/C、独立最终测试与所有失败 seed。模块实验只做到 3 training seeds 时可如实报告，不能表述为已完成 5 seeds，也不能依靠更多 evaluation seeds 替代训练重复。

## 10. 每周交付及论文完成标准

每周结束时，在已有状态入口补充一条宏观进度，并记录已完成事项、真实 run 身份、测试证据、结论边界、下一周前三项任务与资源余额。不要为每次小检查新增一套相似报告。

建议保留以下关键交付物：

1. 第一周：限定诊断报告、基线适配差异表、已测运行成本和最终实验清单。
2. 第二—三周：有限修复（若成立）、MTS 与七分支 QMIX 的实现/测试报告、独立配置与已验证入口。
3. 第四—六周：共同预算多 seed 结果、A/B/C 消融、MTS 模块结果、最终测试和统计汇总。
4. 第七周：完整论文初稿、真实图表和数据索引。
5. 第八周：导师修改闭环、可编译定稿、复现清单与投稿材料。

论文完成至少满足：全文无结果占位；核心贡献均有可追溯证据；基线差异公开；主结果多训练重复且最终测试独立；失败 seed 与成本不隐藏；正文/公式/算法/配置/图表一致；引用题名、DOI 和卷期年份核验；代码、环境、模型和结果身份可重建；导师关键意见逐项回应。

实际投稿、推送新 Release 或向作者发消息不属于本轮动作。本轮只完成审阅、文献适配建议与工作计划。
