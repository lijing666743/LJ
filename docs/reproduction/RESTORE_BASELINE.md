## 为什么保留原实验工作区的Git身份

现有checkpoint记录的训练Git身份是`eb1140cefc4a0ff79b8bd0c05e73c7a23528d7ba`，当前加载器严格检查这个值。直接把现有实验工作区切到新的发布提交，会触发`checkpoint git_commit mismatch`。

因此本次用独立临时索引建立不带旧历史的基线提交及标签，发布到LJ；原工作区HEAD、分支与真实索引保持原样。这样既保存当前源码，也不把旧仓库中的受保护资料和历史文件一并上传。新基线提交的身份与checkpoint原训练身份分别记录，不把两者混同。

从LJ新克隆得到的是发布Git身份，不能未经处理就声称旧checkpoint可直接严格续训。当前电脑的原工作区可继续沿已审计的恢复路线开展实验；迁移到其他工作区或电脑时，需单独处理Git身份、原绝对路径、设备环境和恢复校验。本次不放宽恢复检查，也不修改checkpoint身份。

## 后续实验不好，如何回到现在

在当前工作区，标签是固定回溯点。需要回溯时，先为后续改动另存版本，再从本次标签恢复所需源码、测试和配置；保留原工作区Git HEAD。不要把“切换分支”和“恢复一组文件”混为一件事。

以下命令只查看已保存的版本，不修改实验文件：

```powershell
git show --stat baseline-c32k-20261014
git diff baseline-c32k-20261014 -- src tests experiments
```

真正恢复时，应先保存当前变化，再按明确目录恢复；不要把受保护的knowledge、.agents或后续实验数据纳入批量覆盖。本次没有执行任何回退或清空操作。

如果本地实验资料丢失，从该标签Release下载恢复包及SHA256清单，核验后先解压到空的独立目录，再核对文件数量和内容。确认需要恢复的范围后再合并到实验工作目录，避免覆盖后续结果。归档内路径沿用本项目原相对位置。
