# QMIX v9 seed42：8k训练与冻结评估核验

## 判定

`cpu_pair_q_v9`在本次seed42、8k开发预算下没有改善任务完成数量，未通过预设16k续训门槛。单位完成能耗下降属于完成数与能耗之间的权衡，不能据此宣称CPU联合效用已提高整体任务调度性能。原配置暂不续训至16k/40k，保留模型及数据用于下一项限定诊断。

## 训练确实完成

用户本地完成独立8k CUDA训练，共16回合、225次优化器更新，4k/8k检查点分别对应97/225次更新。第200次更新在环境步7224复制target；全部更新数值有限且实际使用当前权重完整前史。4k至8k有87个online参数张量变化，频率效用分支的四个参数张量全部变化；此前4k的回合与更新记录在8k checkpoint中保留一致。

checkpoint schema v8、CPU效用与探索合同、配置hash、实现源码指纹及独立初始化来源核验通过。训练raw JSONL、aggregate JSON、checkpoint记录与Dashboard CSV逐项一致，真实PNG可解析；各回合reward正项减penalty等于net reward。872项既有保留文件的大小与SHA256未变，未修改C/A/B、环境、reward或当前学习源码。

本次训练生成1943个任务，完成79个（4.07%）；旧v8相同预算为101个。训练中探索触发28167次、贪心触发3833次，共32000个agent决策位置；这些触发包含强制动作位置，不等于动作实际改变。末端epsilon为0.7625。后期loss约0.12至0.16，但net reward仍明显为负，信号状态为signal-watch。训练仍有大量探索，不能与冻结评估混用；冻结评估epsilon为0，也不能把冻结性能不足全部归因于训练epsilon。

## 下一步边界

预先规定的16k候选门槛为完成数超过166且J/完成不高于0.4324177329；本轮两项均未满足。因此不自动扩大训练预算，也不根据本轮结果修改既定判定门槛。

结构能表达队列相关频率偏好，并不保证在当前经验与学习时序下能学好。下一步先限定检查：冻结策略仍在哪些路由/CPU状态误排序；真正完成经验在回放与采样中覆盖多少；完成回报在TD(lambda=0.6)、32-slot chunk和target复制之间怎样传播。高探索、稀疏完成和仅一次target复制是待核查的线索，尚不是根因结论。根据这些证据再决定修改与本地重训，不直接再换网络或续到40k。
