# QMIX延迟完成回报：限定开发试验

## 修改依据与解释边界

v9同预算8k冻结评估完成58/605个，v8为69个，旧v6为166个。新10回合冻结重放精确复现原指标、动作、hidden及外部过程：v9的8k有231个未分配过期；计算资源最多的UAV只接收6个任务。期限容量可行却选Idle/零频率的比例为942/2641，不能将完成数退步只归因于CPU表示。

真实最终回放的225次抽样按原随机流逐次重建并与更新步数、真实样本长度和最终RNG精确核对。71个含完成事件的块被抽取次数中位数18，仅3个完成事件所在块从未抽取；没有证据说主要问题是没有采到完成经验。79个真实完成任务中，分配至完成中位间隔19步，50个跨越32步块；首次CPU服务至完成中位间隔14步，46个跨块。

当前Double-Q TD(λ=0.6)在32步块内反向计算。跨块直接完成奖励系数为0，只能依赖已学bootstrap间接传播；即使拼接后续，λ=0.6在19步后的直接系数也仅约0.00005034。这不等于总Q信用为零，也不构成唯一根因证明。证据原件为`metadata/audits/qmix_v9_failure/20261017/cpu_deadline.json`和`replay_credit.json`。

## 本轮限定改动

候选`episode_return_v10`只调整训练目标组件，但明确包含两项相关改动：

1. 保留32步梯度块与同一抽样流，TD目标沿已收集的同回合连续后续片段计算；回合末终止，不跨回合。正在收集的回合只用已存在的片段，末尾使用真实下一状态bootstrap，不能假造未来数据。
2. 将λ从0.6调整为0.95，γ仍为0.99。对本次79个完成事件，完整后续下分配动作的直接完成系数中位数从0.00005034升到约0.31176。这是目标公式系数的变化，不是性能提升数据。高λ会增加长回报方差及离策略敏感性，须检查TD值、梯度和开发效果。

同一批次按回合合并目标计算，未来信息仅进入detach的训练标签，当前actor每时刻仍只看到原合法观测和过去hidden。online精确合法贪心选动作，target评估；没有将未来观测加入当前actor输入。保留v9 CPU联合Q、Route/TX结构、参数量、环境、reward、所有合法动作、学习率、探索、target间隔200、更新频率和原有开发预算。没有加入Heuristic推理规则。

PyMARL2原作者实现沿传入的完整EpisodeBatch计算TD回报，支持将计算梯度的块长与回报上下文区分；λ=0.95是本项目候选值，不是声称原作者推荐的最优值。参考：[NQLearner](https://raw.githubusercontent.com/hijkzzz/pymarl2/master/src/learners/nq_learner.py)、[TD目标](https://raw.githubusercontent.com/hijkzzz/pymarl2/master/src/utils/rl_utils.py)。两个变化同时试验，不能据结果拆分各自因果贡献。

## 验收与开发预算

先验证跨块奖励、独立整回合返回值、终止与未完成回合bootstrap、回合隔离、前史重建、未来奖励只改变目标、梯度块长度、抽样及随机流、Double-Q、断点续训和旧版本拒绝。再运行实际CUDA短程工程训练与冻结评估，记录真实更新、后续上下文使用、有限数值和文件一致性。工程试跑不算8k开发成绩。

验证通过后从零启动seed42独立8k，4k/8k各用既定五场景605任务冻结评估。主要直接对照为v9的58个、0.4349555965 J/完成；v6的166个、0.4324177329 J/完成为竞争参照。仍须超过166个且单位完成能耗不高于0.4324177329才考虑16k稳定性检查；不因低于C就任意改门槛，不提前推进40k。若无改善，先报告结果，不能把不断改版说成算法有效。
